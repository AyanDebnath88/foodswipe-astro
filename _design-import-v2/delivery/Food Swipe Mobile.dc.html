NAVIGATION · WHY IT CHANGED
the hamburger hid all three top-level destinations behind a tap. Bottom bar: 3 items, icon + label, always visible, current destination in terracotta
bar 62px + 26px home-indicator inset; each item is an 88×48 hit box, ≥8px apart
the swipe controls sit 96px above the bar so the thumb arc never collides with a tab
badge on Saved is a 8px dot, cleared on visit — never a count
bottom bar is top-level only: rounds, results and the celebration are pushed above it and keep the back affordance in the header
STATES · SPEC
skeleton blocks #F2E9DC on #FEFCF9, exact geometry of the real content — space is reserved, so nothing shifts (CLS 0)
skeletons appear only after 300ms of waiting; below that, nothing
empty state: dashed #DEC9B3, one sentence of cause + one recovery CTA. Never a shrug
notices state cause AND fix; offline carries an explicit Retry. Nothing auto-dismisses except the ink toast (4s)
destructive confirm uses #A6503A (5.0:1 on ivory; label #FFF6F0 on it, 5.2:1) — the only red-leaning token in the system, and it never appears outside a confirm
every notice pairs an icon with the colour, so state never depends on hue alone
ACCESSIBILITY AUDIT
targets: like 76 · pass 68 · utility 52 · tab 88×48 — all ≥44pt, ≥8px apart
icon-only controls carry aria-label ("Like Korean", "Pass", "Undo last swipe", "Copy room code")
swipe is never the only route: every gesture has a visible button, and ←/→ work on desktop
focus-visible 2px #D97757 at 2px offset on every interactive element, never animated, never removed
body 15–16px, line-height 1.5, wraps rather than truncates at largest Dynamic Type
prefers-reduced-motion collapses the whole celebration to a 150ms fade; drag tracking stays 1:1 (it is direct manipulation, not decoration)
tap feedback lands within 100ms; loading buttons disable and swap to a spinner instead of going silent
